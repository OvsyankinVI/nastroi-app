# Тестирование

## Автоматические тесты (Dart)

В репозитории есть файл **`test/widget_test.dart`** с пустым телом:

```dart
void main() {}
```

Отдельные **unit** / **widget**-тесты для репозитория, сервисов и экранов в проекте не описаны и не реализованы в этом файле.

Запуск инфраструктуры Flutter-тестов:

```bash
flutter test
```

## Ручная проверка (ориентир для QA)

### Основное приложение

- Сценарий **«Профиль по ссылке» → «Добавить»**: проверить `SharedPreferences` и отсутствие вызовов цепочки виджет/Watch/уведомления до следующего **`HomeScreen._init` / `_persist`**; проверить, что главный экран может показывать устаревший список до перезапуска.
- Установка cold start: загрузка моков или сохранённых данных, сетка людей, поиск, FAB.
- Создание / редактирование / удаление локального человека; импорт по ссылке и по export code.
- Профиль «Я», быстрая смена настроения с главного экрана.
- Жизненный цикл: включение, этапы, сохранение и отражение на главной и в профиле.

### Хранилище

- Удаление приложения и переустановка — проверка восстановления из пустого состояния → моки.
- Перезапуск — сохранность списка в `SharedPreferences`.

### Виджет iPhone

- После изменения людей на телефоне данные в виджете обновляются после вызова `WidgetService` (может потребоваться время WidgetKit).
- Выбор человека в конфигурации виджета (App Intent).
- Тап по виджету открывает приложение с **`nastroi://person/<publicId>`** (если человек есть в базе).

### Apple Watch

- Установка приложения Watch, пара с iPhone.
- После изменений на телефоне список на часах обновляется (WatchConnectivity).
- Выбор «Показать в виджете» и проверка complication.
- Полёт без установленного Watch-приложения: на телефоне ошибки в Dart при `invokeMethod` не должны ломать UI (в коде только `print`).

### Уведомления

- Выдача разрешений на iOS.
- Включённый цикл с корректной датой старта — появление запланированного уведомления к заданному времени (09:00 в логике `NotificationService`).
- После **`rescheduleCycleNotifications`** старые запланированные уведомления плагина сняты (`cancelAll`).

### Deep links

- Открытие **`nastroi://person/<publicId>`** при установленном приложении и наличии человека.
- Сценарии отсутствия человека и ошибок потока ссылок (сейчас без пользовательских сообщений).

### Android

Deep links в манифесте не настроены — полное соответствие iOS-поведению при открытии HTTPS извне не гарантируется без доработки.
